# Design system and accessibility

Purpose: record design requirements supported by visuals without treating mock-up styling as fixed implementation.

Visual assets repeatedly used clear approval/status badges, cards, progress, warnings, timelines and mobile layouts. Exact colours/typography are not confirmed in accessible evidence.

Requirements: semantic headings/forms, keyboard operation, visible focus, labelled status not colour-only, WCAG AA contrast, error summaries and field errors, touch-friendly controls, responsive queue/detail views, reduced motion support and plain-language verification disclaimers.

Admin tables must remain usable on small screens through cards or deliberate responsive patterns—not horizontal truncation of critical actions.
