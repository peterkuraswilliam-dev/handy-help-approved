# Glossary

Purpose: keep product language consistent.

| Term | Meaning |
| --- | --- |
| Contractor invitation | A secure sign-up link created by the app owner or an authorised admin. It permits contractor account creation/onboarding but does not confer approval. |
| Approved contractor | A contractor application accepted by an authorised admin under the current verification standard. Not a workmanship guarantee. |
| Verified job | A customer job checked and approved by admin before matching/circulation. |
| Match | A controlled association between an approved job and a suitable contractor. |
| Selected contractor | The contractor chosen by the customer for the job. Exact legal/booking effect is open. |
| Contact protection | Preventing premature exchange or display of personal contact details. |
| Job Rescue | Proposed local-admin intervention when a job stalls, is cancelled or encounters a problem. |
| Service area | Locations/radius in which a contractor works. Data model is open. |
| RLS | Supabase Row Level Security enforcing database access independent of the frontend. |
| Service role | Trusted server credential that bypasses RLS; never expose to a client. |
| Founding member | Early participant recruited during development; benefits and permanence are open. |
